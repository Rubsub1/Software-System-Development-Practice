# 简化广州中考公办高中录取模拟系统

本仓库用于保存课程设计的需求分析、数据库设计、软件实现和测试等成果。项目以简化的广州中考公办高中招生规则为背景，模拟四个批次的投档过程，并支持结果查询和统计。

技术方案：Web 前端使用 **TypeScript**，后端使用 **Python**，数据库使用 **SQLite**，通过 **Docker** 部署运行。Python Web 框架及前端构建工具可在开发前选定；Docker 配置和启动命令在实现后补充。

项目状态：需求与设计阶段。以下功能和交付物为计划内容，实际进展以仓库记录为准。后续目标是使用 **15 万名虚构考生**进行贴近业务的数据模拟和完整投档，数据规模不代表使用真实考生信息。

## 分工

林伟翔负责投档核心、算法优化及大规模运行验证施旭锋 负责数据库、15 万考生数据生成及数据性能；周俊任 负责界面和结果展示。每项工作均有负责人；成员姓名和实际 Issue 链接确定后补充。

### 系统实现

| 负责人 | 任务 | 完成条件和成果 |
| --- | --- | --- |
| 林伟翔 | 第一批自主招生 | 实现志愿、资格和计划控制线校验，按校内考核排名录取；立即更新录取状态和余额。 |
| 林伟翔 | 第二至第四批投档 | 按批次、梯度和志愿轮次处理，同计划按总分降序及同分序号升序排序；第二批按高中与所属初中隔离名额。 |
| 林伟翔 | 结转、运行控制和日志 | 支持按批及完整运行；第一、二批剩余名额仅一次转入本校第三批，保存录取、跳过原因与结转流水，重试不得重复录取或结转。 |
| 林伟翔 | 投档性能优化 | 分析排序、分组、扫描和内存使用，减少重复计算；在规则正确和结果可复现的前提下优化 15 万考生的完整投档。 |
| 林伟翔 | 统计口径与结果服务 | 实现计划数、录取人数、完成率、未录取人数、分数分布以及最低分和末位考生的计算，提供查询结果供界面展示；无人录取时显示“无”。 |
| 施旭锋 | 数据库实现和一致性 | 实现表结构、约束、索引及事务；保存输入版本、计划余额和运行结果，保证录取、余额与结转更新一致。 |
| 施旭锋 | 大规模数据库性能 | 根据实际查询设计索引和批量写入，检查执行计划、事务开销和数据库大小，支持 15 万考生数据导入与查询。 |
| 施旭锋 | 基础数据管理 | 实现高中、初中、考生、成绩、计划、资格和志愿的录入、修改、导入与校验；拒绝非法或重复数据。 |
| 施旭锋 | 15 万考生数据生成 | 生成可复现的 15 万名虚构考生及其学校、成绩、同分序号、计划、资格和志愿；配置合理的业务分布，保存随机种子和生成参数，校验唯一性与引用关系。 |
| 周俊任 | TypeScript Web 界面与运行展示 | 提供数据操作、投档运行、进度、计划余额及结转情况的界面，调用 Python 后端接口，输入错误能定位。 |
| 周俊任 | 结果展示与导出 | 对接 林伟翔 提供的查询和统计结果，展示考生、高中、初中、批次和计划的名单、余额、原因、最低分及末位考生，并提供导出入口。 |

## 使用步骤

1. 阅读课程设计任务书和设计讨论提示，了解项目范围及统一简化规则。
2. 查看[需求分析](需求分析.md)，按照三人分工开展建模、人工预测试和实现工作。
3. 按 TypeScript 前端、Python 后端、SQLite 和 Docker 方案开发，具体依赖及启动方式在实现后补充。
4. 先准备小规模模拟数据和人工预期，再开发完整投档功能，并对照预期检查结果。
5. 使用 Git 记录真实协作过程，逐步补充源代码、数据库脚本、测试结果和部署说明。

## 阶段安排

1. **需求与计划**：梳理业务范围、投档规则、测试场景和三人分工。
2. **建模与预测试**：完成数据模型和表结构设计，使用小数据集进行独立人工推演。
3. **实现与集成**：开发数据管理、四批次投档、结果查询和统计功能，并进行模块联调。
4. **测试与交付**：林伟翔、施旭锋 完成正确性和 15 万考生规模测试；周俊任完成界面检查与演示，整理部署和使用说明。

系统使用虚构数据；第一、二批剩余名额结转至本校第三批，详细投档顺序和验收要求以[需求分析](需求分析.md)为准。本项目为教学模拟，不代表现实招生政策的全部规则。
